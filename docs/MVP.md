# Interna: видение MVP-прототипа

> Рабочий документ. Версия 0.2, ноябрь 2026: графика переведена с 2D-изометрии на 3D-диораму.

## 1. Суть в одном предложении

**Уютная комната, которую вы обставляете своими вещами (книгами, музыкой, фото), и в которой живёт ИИ-персонаж, который с этими вещами взаимодействует.**

## 2. Что проверяем

Прототип нужен не для того, чтобы «сделать продукт», а чтобы ответить на один вопрос:

> **Возвращаются ли люди в комнату сами, потому что там живёт персонаж?**

Всё, что не помогает ответить на этот вопрос, в MVP не входит.

### Критерии успеха (на 10–20 тестировщиках, 2–3 недели)

| Метрика | Хороший сигнал |
|---|---|
| Возвращаются на следующий день (D1) | > 50% |
| Возвращаются через неделю (D7) | > 25% |
| Добавили хотя бы 5 своих вещей (книг, треков, фото) | > 60% |
| Сами начали разговор с персонажем 3+ раза | > 50% |
| Ответ на вопрос «Расстроишься, если прототип исчезнет?» | «да» у трети и больше |

## 3. Главный цикл

```
Обставил комнату ──► Положил туда свои вещи ──► Персонаж ими пользуется
        ▲                                              │
        │                                              ▼
Возвращаешься посмотреть ◄── «Пока тебя не было…» ◄── Персонаж живёт сам
```

Главная фишка: **персонаж знает ваши вещи и реагирует на них**. Он берёт книгу с полки и потом говорит о ней, включает трек из колонки под настроение, пишет в дневник, пока вас нет.

## 4. Что входит в MVP

### 4.1 Комната
- **3D-диорама**: комната как «кукольный домик», низкополигональный стиль.
- **Камера**: вид сверху под углом. Можно вращать вокруг комнаты (с шагом 90° или плавно) и приближать. Свободного перемещения нет.
- **Стены**: две ближние к камере стены автоматически прячутся или становятся прозрачными.
- Логика комнаты остаётся на сетке примерно 10×10 клеток. Сетка нужна для расстановки, проверки коллизий и поиска пути, визуально её не видно.
- Выбор пола и обоев: 3–4 варианта (материалы и текстуры).
- Режим редактирования: поставить, передвинуть, повернуть, удалить предмет. Видна подсветка клеток и «призрак» предмета, красный, если поставить нельзя.
- Реальное время суток: направленный «солнечный» свет из окна меняет угол и цвет утром, днём и ночью. Ночью комнату освещают только лампы.

### 4.2 Каталог (~15 предметов)

| Предмет | Компоненты | Взаимодействие |
|---|---|---|
| Книжный шкаф | `container<book>` | добавить книгу (название, автор, заметка, обложка), открыть список |
| Колонка | `media<audio>` | плейлист из своих аудиофайлов, play/pause/next |
| Рамка для фото | `display<image>` | выбрать фото с диска |
| Лампа / торшер | `light` | вкл/выкл, настоящий точечный источник света |
| Письменный стол | `container<note>` | заметки и дневник персонажа |
| Диван, кресло, стул | `seat` | персонаж садится |
| Кровать | `seat`, `bed` | персонаж спит ночью |
| Растение | `needs` | его можно полить (это может сделать и персонаж) |
| Окно | `window` | показывает время суток |
| Ковёр, полка, тумба, декор | — | только декор |

### 4.3 Персонаж (один)
- **Внешность**: 3–4 готовых модели, у всех общий «скелет» (риг). Плюс смена цвета волос, кожи и одежды через материалы. Без полноценного конструктора, но общий скелет позволит позже менять детали (причёски, одежду) как отдельные части модели.
- **Анимации**: общий набор для всех моделей: idle, ходьба, сидя, чтение, сон, полив, жесты при разговоре. Переходы между анимациями плавные.
- **Характер**: имя, 3–5 черт из списка (спокойный, любопытный, ворчливый, мечтательный…), свободное описание в пару предложений, любимые занятия.
- **Жизнь в комнате**: ходит по сетке, садится, читает, включает музыку, поливает растение, спит ночью.
- **Разговор**: панель чата. Персонаж знает, что стоит в комнате и что лежит в шкафу.
- **Память**: дневник событий и короткий список «фактов о хозяине».
- **«Пока тебя не было…»**: при запуске показывается карточка с 2–4 событиями за время отсутствия.

### 4.4 Сохранение
- Мир хранится на сервере как один JSON-документ.
- Медиафайлы (аудио, фото) для MVP хранятся **локально** на устройстве. На сервер уходят только метаданные.
- Вход по инвайт-коду, без полноценной регистрации.

## 5. Что НЕ входит в MVP

- ❌ Гости и мультиплеер (самая дорогая часть, это следующий этап).
- ❌ Несколько комнат и порталы.
- ❌ Несколько персонажей.
- ❌ Полноценный конструктор внешности.
- ❌ Свои модели или спрайты предметов от пользователей.
- ❌ Интеграции со Spotify, YouTube и т. п.
- ❌ Монетизация, магазин, валюта.
- ❌ Мобильная версия.

## 6. Технический стек

Под имеющийся опыт: JS/TS, React, Node/NestJS.

| Слой | Выбор | Почему |
|---|---|---|
| Клиент | **Vite + React + TypeScript** | знакомый стек |
| 3D-сцена | **React Three Fiber** (Three.js) | сцена описывается React-компонентами, родная среда для React-разработчика |
| Помощники | **@react-three/drei** | камеры, загрузка glTF, анимации, тени, окружение, HTML-подписи в сцене |
| Постобработка | `@react-three/postprocessing` (по желанию) | мягкое свечение ламп, лёгкое затемнение краёв: сильно добавляет уюта |
| UI поверх сцены | React (каталог, инспектор, чат) | обычный DOM поверх `<Canvas>` |
| Состояние | **Zustand** (+ Immer) | единый стор мира; и сцена, и UI читают из него |
| Поиск пути | `pathfinding` / `easystarjs` (A*) | по логической сетке комнаты, как и в 2D |
| Физика | не нужна | коллизии и расстановка решаются сеткой |
| Десктоп | **Electron** (позже) | разрабатываем как веб-приложение, в оболочку заворачиваем в конце: так гостевой доступ через браузер останется возможным |
| Бэкенд | **NestJS** | хранение миров, прокси к LLM (ключ API не должен лежать в клиенте) |
| БД | **PostgreSQL + Prisma** | мир хранится в колонке JSONB, плюс таблицы памяти и событий |
| LLM | Kimi K3 (Moonshot); провайдер переключается на Claude переменной окружения | вызовы идут только через бэкенд, токены логируются с первого дня |
| Модели | бесплатные CC0-наборы низкополигональной мебели и персонажей (Kenney, Quaternius) | единый стиль без художника |
| Анимации | Mixamo или анимации из того же набора персонажей | один скелет, общие анимации |
| Инструменты | **Blender** (базовый уровень), `gltf-transform` | подогнать масштаб и точку вращения, сжать модели |

### Подготовка моделей (pipeline)

Один раз договориться о правилах и проверять по ним каждую модель:

- Формат **glTF/GLB**. Единицы измерения — метры, 1 клетка = 0,5 м (или 1 м, главное одинаково для всех).
- Точка вращения (pivot) — в центре основания предмета, «перёд» смотрит в одну сторону.
- Сжатие геометрии и текстур через `gltf-transform` (Draco/Meshopt, KTX2) скриптом в репозитории.
- Общая палитра или текстурный атлас, чтобы предметы из разных наборов смотрелись вместе.
- У персонажей один скелет, анимации хранятся отдельно и подключаются к любой модели.

### Структура репозитория

```
interna/
├─ apps/
│  ├─ client/        # Vite + React + React Three Fiber
│  └─ server/        # NestJS
├─ packages/
│  └─ shared/        # общие TS-типы: World, ObjectDef, Character, Action
├─ assets/
│  ├─ source/        # исходные модели (.blend, .fbx, .glb из наборов)
│  └─ scripts/       # скрипты сжатия и проверки glTF
└─ docs/
```

pnpm workspaces. Общие типы — главная ценность монорепо: клиент, сервер и ИИ-«инструменты» описаны одними и теми же типами.

## 7. Модель данных (черновик)

```ts
// Каталог: описание типа предмета (статично, в коде)
interface ObjectDef {
  id: string;                 // 'bookshelf_oak'
  name: string;
  model: string;              // путь к .glb
  footprint: { w: number; h: number };  // в клетках сетки
  height: number;             // нужно, чтобы ставить предметы на полки и столы позже
  components: ComponentDef[]; // [{ type: 'container', accepts: 'book', capacity: 30 }]
}

// Предмет, поставленный в комнату
interface PlacedObject {
  id: string;
  defId: string;
  x: number; z: number;       // клетка на сетке пола (в 3D «вверх» — это ось y)
  rotation: 0 | 90 | 180 | 270;
  state: {
    container?: ItemRef[];
    media?: { playlist: TrackRef[]; current?: string; playing: boolean };
    display?: { imageRef: string };
    light?: { on: boolean };
    needs?: { water: number };     // 0..1
  };
}

interface World {
  id: string;
  ownerId: string;
  room: { floor: string; wall: string; size: { w: number; h: number } };
  objects: PlacedObject[];
  character: Character;
  lastVisitAt: string;
}

interface Character {
  id: string;
  name: string;
  appearance: { model: string; hairColor: string; skinColor: string; outfitColor: string };
  personality: { traits: string[]; description: string; likes: string[] };
  position: { x: number; z: number };
  activity: Activity;          // 'idle' | 'walking' | 'sitting' | 'reading' | 'sleeping'...
}

// Память: отдельные таблицы, не внутри World
interface MemoryEntry { characterId: string; kind: 'event' | 'fact' | 'summary'; text: string; createdAt: string; }
```

## 8. Как устроен «живой» персонаж

Ключевая идея: **LLM решает, а игра исполняет.** Модель не управляет анимацией напрямую. Она выбирает действие из списка, а движок его проигрывает: строит путь по сетке, ведёт персонажа к предмету, поворачивает лицом к нему и включает нужную анимацию.

### 8.1 Действия как инструменты (tool use)
Список действий строится из компонентов предметов, которые стоят в комнате:

```
walk_to(objectId)        sit(objectId)          sleep(bedId)
read_book(bookId)        play_music(trackId)    stop_music()
toggle_light(lampId)     water_plant(plantId)   write_diary(text)
say(text)                idle(minutes)
```

Добавили растение — у персонажа появилось действие `water_plant`. Новые предметы автоматически расширяют поведение.

### 8.2 Цикл поведения
1. **Простая логика без ИИ** (бесплатно, работает постоянно): блуждать, садиться, ночью спать.
2. **Решение с помощью LLM** (раз в несколько минут или по событию): «вот комната, вот время, вот что ты недавно делал. Что дальше?» Модель возвращает 1–3 действия.
3. **События-триггеры**: хозяин добавил книгу, вошёл в комнату или долго молчит. В ответ идёт реакция персонажа.

### 8.3 Контекст для модели
- Системный промпт: характер, имя, правила («говори коротко», «ты живёшь в этой комнате»).
- Компактное описание комнаты: предметы, содержимое шкафа, текущий трек, время суток.
- Последние N событий из дневника, факты о хозяине, сжатое резюме старой памяти.

### 8.4 «Пока тебя не было…»
При запуске считаем, сколько прошло времени, и одним запросом просим модель сгенерировать 2–4 правдоподобных события, используя только доступные действия. Изменения применяются к миру (книга отмечена прочитанной, растение полито, запись в дневнике), а пользователю показывается карточка.

Это **один дешёвый запрос на визит**, а не постоянная симуляция в фоне.

### 8.5 Контроль стоимости
- Логировать токены на каждый вызов с первого дня.
- Лимит LLM-решений в час и лимит сообщений в день на пользователя.
- Резюмировать память, а не отправлять в модель всю историю.

## 9. План работ

Оценка в неделях сфокусированной работы. Если работать по вечерам, умножайте примерно на 2.

| Неделя | Результат |
|---|---|
| 0 (освоение) | Основы Three.js и React Three Fiber на маленьких примерах; Blender на уровне «открыть, поправить масштаб и pivot, экспортировать» |
| 1 | Монорепо, `<Canvas>`, пол и стены, камера-диорама (вращение и зум), базовый свет |
| 2 | Подбор моделей, pipeline сжатия, 10–15 предметов в едином стиле загружаются в сцену |
| 3 | Каталог, расстановка по сетке, «призрак» и подсветка клеток, поворот, удаление, прячущиеся стены, локальное сохранение |
| 4 | Компонентная система, шкаф с книгами, рамка с фото, лампа как настоящий источник света, время суток |
| 5 | Колонка и плейлист из локальных файлов; бэкенд NestJS, сохранение мира в Postgres, инвайт-коды |
| 6 | Персонаж: модель, набор анимаций с плавными переходами, A*, движение по пути, конечный автомат поведения без ИИ |
| 7 | Чат с персонажем через бэкенд, характер в системном промпте, знание комнаты |
| 8 | Действия как инструменты, решения от LLM, реакции на события |
| 9 | Память (дневник, факты, резюме), «Пока тебя не было…» |
| 10 | Атмосфера: мягкие тени, постобработка, звуки; оптимизация |
| 11 | Сборка в Electron, онбординг (шаблон комнаты и знакомство с персонажем) |
| 12–14 | Тестирование на людях, метрики, интервью, правки |

**Первый ощутимый результат** — к концу недели 3: можно обставить 3D-комнату.
**Первый «вау-момент»** — к концу недели 8: персонаж сам подходит к полке и берёт вашу книгу.

> Правило для недель 1–4: если что-то в графике занимает больше дня и не мешает главному циклу, оно уходит в бэклог. Красоту наводим на неделе 10.

## 10. Риски прототипа

| Риск | Что делаем |
|---|---|
| Графика выглядит дёшево, тестировщики не «влюбляются» | единый низкополигональный стиль, общая палитра, тёплый свет и мягкие тени, музыка |
| Модели из разных наборов не сочетаются | основа из одного-двух наборов, остальное только с перекраской под общую палитру |
| Утонул в 3D: шейдеры, свет, эффекты | правило «больше дня на графику → в бэклог» до недели 10 |
| Освоение Three.js затянулось | неделя 0 на маленьких примерах, готовые решения из `drei` вместо своих |
| Тормозит на слабых ноутбуках | одна направленная тень, запечённое окружение, сжатые модели, ограничение числа ламп с тенями |
| Персонаж ведёт себя скучно или повторяется | разнообразие действий, случайность, память о прошлом, реакции на новые вещи |
| Персонаж «ломает» мир, выдумывая несуществующие предметы | только инструменты со строгой проверкой `objectId` |
| Стоимость ИИ растёт | лимиты, дешёвая модель, логи токенов |
| Ушёл в перфекционизм движка | всё, что не помогает главному циклу, переносится в бэклог |

## 11. Открытые решения

- [x] **Визуальный стиль**: 3D-диорама с фиксированной камерой, низкополигональный стиль.
- [ ] **Камера**: вращение с шагом 90° (проще, стены прячутся предсказуемо) или плавное.
- [ ] **Пропорции персонажа**: «чиби» (крупная голова, мило, прощает простые анимации) или ближе к реальным пропорциям.
- [ ] **Язык персонажа**: только русский или русский и английский. Пока персонаж отвечает на языке хозяина, по умолчанию по-русски.
- [x] **Тон персонажей по умолчанию**: друг — тёплый, внимательный, с мягким юмором, говорит коротко. Имя редактируется (по умолчанию «Саша»).
- [ ] **Музыка**: только свои файлы или ещё вставка ссылок.
- [x] **Где хранить мир в MVP**: и там, и там. Мир живёт в браузере и работает без сети, а копия синхронизируется с сервером (NestJS + Postgres) с проверкой версий; медиафайлы остаются на устройстве.

## 12. Следующий этап (после успешного MVP)

1. Гостевой просмотр по ссылке (только чтение, в браузере).
2. Несколько комнат и двери.
3. Второй персонаж, персонажи общаются друг с другом.
4. Конструктор внешности: причёски, одежда и аксессуары как сменные части модели на общем скелете.
5. Гости в реальном времени.
